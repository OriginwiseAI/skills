# SOP-to-Training-Video Review Checklist

**Use this before approving a training walkthrough based on an SOP or controlled procedure.**

## 1. Scope the learning job

- [ ] Viewer role: ______________________________
- [ ] One outcome after viewing: ______________________________
- [ ] When this walkthrough should be used: ______________________________
- [ ] What it must *not* be used for: ______________________________
- [ ] Prerequisite knowledge, equipment, or permissions: ______________________________

## 2. Identify the source of truth

- [ ] Source title and link/attachment: ______________________________
- [ ] Current version/date: ______________________________
- [ ] Source owner: ______________________________
- [ ] Related controlled documents or job aids: ______________________________
- [ ] Location of sensitive, access-controlled, or versioned details: ______________________________

## 3. Preserve non-negotiable information

Mark each item that must remain unchanged or visibly qualified in the explanation.

- [ ] Required order of actions
- [ ] Warnings and prerequisites
- [ ] Numbers, thresholds, units, or dates
- [ ] Terms and labels the viewer must recognize later
- [ ] Safety, quality, security, or compliance boundaries
- [ ] Exception, stop, or escalation conditions
- [ ] Required evidence or record to capture
- [ ] Other: ______________________________

## 4. Map the decision path

| Beat | Viewer sees | Decision or action | Evidence to preserve | Owner of next step |
| --- | --- | --- | --- | --- |
| Trigger |  |  |  |  |
| First safe check |  |  |  |  |
| Normal path |  |  |  |  |
| Exception / stop condition |  |  |  |  |
| Escalation / handoff |  |  |  |  |
| Final confirmation |  |  |  |  |

## 5. Review before release

- [ ] A subject-matter reviewer confirmed terms, sequence, and boundaries.
- [ ] The video points back to the current source where needed.
- [ ] The normal path does not hide an exception or stop condition.
- [ ] Each visual element proves a relationship, action, or decision; none is merely decorative.
- [ ] Claims, labels, charts, and screenshots are readable and current.
- [ ] The output has an update owner and a revision trigger.

## 6. Record the update trigger

**Re-review this explanation when:**

- [ ] The source version changes.
- [ ] A product, policy, tool, or process changes.
- [ ] An incident exposes a missing branch or unclear handoff.
- [ ] The process owner changes.
